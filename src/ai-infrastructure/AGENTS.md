# 项目协作要求

## 重要：教学环境必须可复现

本项目用于教学。任何变更都必须考虑学生能否仅凭项目文件和明确步骤复现，不能只让教师当前机器能够运行。

- **操作运行环境前，必须先向用户说明。** 涉及容器内部文件、Docker 数据卷、数据库、账号权限、插件状态、服务重启或重建时，事先说明具体改动、影响、持久化位置、回滚方式以及学生的复现步骤，不得先改完再告知。
- **优先把配置保存在项目文件中，通过 Docker Compose 或明确的初始化步骤应用。** 不得把直接修改容器或数据卷产生的隐藏状态作为最终方案。确需临时修改时，先说明原因，并在完成后交代如何纳入可复现的项目配置。
- 严格控制改动范围；只读排查期间不得写入运行环境。用户说“不要改代码”或“只解释原因”时，不能据此推定允许修改容器、数据库、权限或其他运行状态。
- 验证方案时，不得擅自清空数据卷、重置数据库或覆盖学生需要保留的数据。区分静态配置检查、当前环境验证和全新环境复现，未实际验证的部分必须明确说明。
- 完成后逐项说明主动修改的项目文件、容器文件、数据卷内容、数据库或权限状态，以及执行过的重启、重建操作；不能只汇报 Git 中的代码差异。

## 沟通规范

**非常重要：**

1. 当用户提问时，不能修改任何东西，不能新增任何东西，不能删除任何东西，仅回答用户问题即可
2. 回答问题要言简意赅，不要长篇大论，用户有不明白的地方会自行追问

## 课件规范

- 某些课件以 **Jupyter Notebook** 格式编写
- 使用 VS Code 的 Jupyter 插件运行
- Jupyter 的 Python 解释器必须使用**当前工程的虚拟环境**中的解释器，切勿使用其他环境

## 工程管理

- 使用 **UV** 进行工程管理
- 安装依赖时，统一使用 UV 格式：`uv add <package>`
- **绝对不允许擅自进行 git 操作，除非用户特别要求**
- 当用户要求你在某一个分支上工作时，你首先应该检查该分支是否有对应的工作树；如果有，就应该在工作树上进行工作。
