## 3. schema

需要新增的 schema 有 3 个，均在 `quality.py` 文件里面：

```py
class QualityIssue(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)
    code: Literal[
        "hard_rule",
        "plot_gap",
        "character_inconsistent",
        "visual_unclear",
        "motion_conflict",
    ]
    severity: Literal["error", "warning"]
    shot_id: str | None = Field(default=None, pattern=r"^shot_[a-z0-9_]+$")
    description: str = Field(min_length=1)
    suggestion: str = Field(min_length=1)
```

QualityIssue 一条具体问题，说明哪一镜、什么错、怎么改。

- `code`：问题类型。
  - 硬规则失败是 `hard_rule`；
    - 分镜没通过 Python 硬规则。镜头数量、shot_id、顺序、时长、角色或场景引用这类问题走这里。它由 hard_rules_failed 写入，模型评价不会产出这个码。
  - 模型语义问题是 `plot_gap`、`character_inconsistent`、`visual_unclear`、`motion_conflict`
    - plot_gap：故事因果或镜头衔接断了。例如核心动作没交代、前后镜头对不上、动作在该镜头的秒数里讲不清。
    - character_inconsistent：角色、场景或关键道具前后不一致。例如同一角色外观或服装变了，道具的来源、数量、持有者互相矛盾。
    - visual_unclear：画面描述不够，首帧或尾帧无法据此生成。核心人物、道具或空间关系缺失，导致画面表达不明确。
    - motion_conflict：镜头里的动作和摄影机运动互相矛盾。例如同一镜头既要求固定机位，又要求摄影机跟拍。
- `severity`：`error` 会卡住，`warning` 不挡通过
- `shot_id`：对应哪一镜，例如 `shot_03`；全局问题可以为空
- `description` / `suggestion`：问题和改法



```py
class StoryboardQualityReport(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)
    is_passed: bool
    summary: str = Field(min_length=1)
    issues: list[QualityIssue]
    affected_shot_ids: list[str]

    @model_validator(mode="after")
    def check_consistency(self):
        blocking = any(issue.severity == "error" for issue in self.issues)
        if self.is_passed == blocking:
            raise ValueError("is_passed 必须与 error 级问题一致")
        expected = {issue.shot_id for issue in self.issues if issue.shot_id}
        if set(self.affected_shot_ids) != expected or len(
            self.affected_shot_ids
        ) != len(expected):
            raise ValueError("affected_shot_ids 必须与问题中的 shot_id 一致且不重复")
        return self
```

StoryboardQualityReport 是写入图的 State 里面的。除了问题列表，还带：

- `is_passed`：能不能过
- `summary`：一句话结论
- `affected_shot_ids`：出问题的镜头 ID

`check_consistency` 方法用于做一致性检查，保证「过没过」和「涉及哪些镜头」对得上，对不上就直接报错，不让脏报告进 State。



**注意点1**

```py
blocking = any(issue.severity == "error" for issue in self.issues)
if self.is_passed == blocking:
    raise ValueError("is_passed 必须与 error 级问题一致")
```

`blocking` 表示有没有 `error` 级问题，只要有一条 severity 是 error，本轮就应判定为阻断（不能通过）。

```py
blocking = any(issue.severity == "error" for issue in self.issues)
# blocking 就是在看有没有 error 级的错误，只要有 1 个，blocking 就是 True

# 等价于
blocking = False
for issue in self.issues:
	if issue.severity == "error":
		blocking = True
		break
```

is_passed 和 blocking 必须相反：有 error 就不能通过，没有 error 就必须通过。





**注意点2**

```py
expected = {issue.shot_id for issue in self.issues if issue.shot_id} # 集合
if set(self.affected_shot_ids) != expected or len(self.affected_shot_ids) != len(expected):
```

`affected_shot_ids` 必须和问题里的镜头对得上。

从 issues 里收集所有非空 `shot_id`，再和 `affected_shot_ids` 比：

- 集合要一样：不能少报、也不能多报无关镜头
- 长度也要一样：`affected_shot_ids` 里不能有重复



校验通过就 `return self`，这份报告可以写入 `quality_report`，后面 `route_quality` 才能放心看 `is_passed`。



```py
class ModelQualityReport(BaseModel):
    """模型只生成问题事实，正式通过判断由 Python 推导。"""

    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)
    summary: str = Field(min_length=1)
    issues: list[QualityIssue]

    def to_report(self) -> StoryboardQualityReport:
        return StoryboardQualityReport(
            is_passed=not any(i.severity == "error" for i in self.issues),
            summary=self.summary,
            issues=self.issues,
            affected_shot_ids=sorted({i.shot_id for i in self.issues if i.shot_id}),
        )
```

给真实模型（`ArkTextModel`）用的输出格式。只有 `summary` 和 `issues`，没有 `is_passed` 和 `affected_shot_ids`。

关系可以看成：

```
模型输出 ModelQualityReport
        ↓ to_report()
   StoryboardQualityReport   ← 图里用这份
        └── issues: [QualityIssue, ...]
```

## 5. prompt

`quality_prompt.py`

```py
QUALITY_PROMPT = """你是短篇漫剧的分镜质量评价者，只评价输入中的既有分镜，不改写分镜，也不新增角色和场景。
检查故事因果与动作时间预算、相邻镜头衔接、角色和场景一致性、首尾帧可生成性，以及视频动作与摄影机运动是否矛盾。
只报告 Python 硬规则无法判断的语义问题，不重复检查 ID、数量、时长总和与引用是否存在。
问题 code 只能为 plot_gap、character_inconsistent、visual_unclear、motion_conflict；severity 只能为 error 或 warning。
error 仅用于有具体文本依据的核心因果断裂、无法兼容的状态矛盾，或会使核心画面/动作无法明确表达的缺失；不能仅因可进一步润色就判 error。
warning 用于局部描述不足、可合理推断的非核心省略、风格细化和不影响主要叙事的改进；合理切镜与奇幻设定本身不是错误。
判断时结合完整分镜、大纲及角色场景设定，指出冲突字段或前后镜头证据；不能把每个镜头未重复全部设定当成缺失，不能凭空推断不存在的能力限制。
判例：核心动作是角色返回入口，但首帧明确只有空房间且没有后续入画动作，属于 error；若只是人物衣服未逐帧重述且已有角色设定，通常不阻断。
判例：关键入口位置改变却没有动作或既有规则解释，且影响返回路径，属于 error；相邻镜头已明确交代转移则不再报同一错误。
判例：普通糖果从整颗变半颗，若可合理省略进食且不影响结局，至多 warning；若是关键唯一信物且出现互相矛盾的来源、数量，影响核心因果，才判 error。
判例：固定机位下人物走动或观众视线跟随手势不构成摄影机矛盾；只有明确同时要求固定摄影机与摄影机跟拍等互斥指令才报告。
每轮按相同判据评价，允许没有问题时 issues=[]；建议必须在现有设定下可执行，不要求加入与需求冲突的新规则。
shot_id 必须来自输入中的分镜；全局问题用 null。只返回 summary、issues；is_passed 和 affected_shot_ids 均由 Python 根据 issues 推导，不要输出这两个字段。
每条问题都给出具体说明与可执行的修改建议；不通过的依据必须体现为具体 error 级问题，不能只在 summary 中宣称不通过。"""
```

🤔 为什么要模拟 `invalid_report` ?

模型有时输出的 report 存在问题：

- `shot_id` 乱写（`shot_3`、`3`、`镜头三`）
- `affected_shot_ids` 和 issues 对不上，或重复
- 多吐字段、缺字段、JSON 不完整

例如：

```py
{
    "is_passed": True,
    "summary": "错误报告",
    "issues": [
        {
            "code": "plot_gap",
            "severity": "error",
            "shot_id": "shot_03",
            "description": "转场跳跃",
            "suggestion": "补充过渡",
        }
    ],
    "affected_shot_ids": ["shot_03"],
}
```

进行模型评审模拟：

```py
def evaluate_storyboard_quality(
        self,
        requirement: CreativeRequirement,
        outline: StoryOutline,
        characters: list[CharacterProfile],
        scenes: list[SceneProfile],
        storyboard: list[StoryBoard],
        previous_report: StoryboardQualityReport | None = None,
    ) -> StoryboardQualityReport:
        # FAKE_QUALITY_FAULT=invalid_report 时进入。
        # 返回一份「长得像报告、实际校验不过」的裸 dict：
        # is_passed=True 却带 error，构造 StoryboardQualityReport 会失败。
        # 用来模拟模型输出脏数据。
        if self._quality_fault == "invalid_report":
            return {
                "is_passed": True,
                "summary": "错误报告",
                "issues": [
                    {
                        "code": "plot_gap",
                        "severity": "error",
                        "shot_id": "shot_03",
                        "description": "转场跳跃",
                        "suggestion": "补充过渡",
                    }
                ],
                "affected_shot_ids": ["shot_03"],
            }
        # FAKE_QUALITY_FAULT=plot_gap 时进入。
        # 返回合法但不通过的报告：第三镜情节断裂（plot_gap）。
        if self._quality_fault == "plot_gap":
            return StoryboardQualityReport(
                is_passed=False,
                summary="第三镜头与故事设定衔接不足",
                issues=[
                    QualityIssue(
                        code="plot_gap",
                        severity="error",
                        shot_id="shot_03",
                        description="第三镜头缺少寻找过程",
                        suggestion="交代寻找与发现的因果",
                    )
                ],
                affected_shot_ids=["shot_03"],
            )
        # FAKE_QUALITY_FAULT=character_inconsistent 时进入。
        # 返回合法但不通过的报告：第三镜阿沐服装和角色设定不一致。
        if self._quality_fault == "character_inconsistent":
            return StoryboardQualityReport(
                is_passed=False,
                summary="第三镜头角色外观与设定不一致",
                issues=[
                    QualityIssue(
                        code="character_inconsistent",
                        severity="error",
                        shot_id="shot_03",
                        description="阿沐在第三镜头换成了与设定不符的服装",
                        suggestion="改回角色设定中的暖黄色外套与白色裙子",
                    )
                ],
                affected_shot_ids=["shot_03"],
            )
        # FAKE_QUALITY_FAULT=visual_unclear 时进入。
        # 返回合法但不通过的报告：第三镜首帧写不清人物和办公桌的空间关系。
        if self._quality_fault == "visual_unclear":
            return StoryboardQualityReport(
                is_passed=False,
                summary="第三镜头首帧无法明确生成",
                issues=[
                    QualityIssue(
                        code="visual_unclear",
                        severity="error",
                        shot_id="shot_03",
                        description="首帧没有写出人物与办公桌的空间关系",
                        suggestion="在首帧补上人物位置和关键道具",
                    )
                ],
                affected_shot_ids=["shot_03"],
            )
        # FAKE_QUALITY_FAULT=motion_conflict 时进入。
        # 返回合法但不通过的报告：第三镜固定机位和跟拍指令互相矛盾。
        if self._quality_fault == "motion_conflict":
            return StoryboardQualityReport(
                is_passed=False,
                summary="第三镜头的动作与摄影机运动矛盾",
                issues=[
                    QualityIssue(
                        code="motion_conflict",
                        severity="error",
                        shot_id="shot_03",
                        description="camera_motion 要求固定机位，video_prompt 却要求摄影机跟拍",
                        suggestion="统一为固定机位，把人物走动只写进动作",
                    )
                ],
                affected_shot_ids=["shot_03"],
            )
        # 走到这里：FAKE_QUALITY_FAULT=none，返回合法且通过的空问题报告。
        return StoryboardQualityReport(
            is_passed=True,
            summary=f"{len(storyboard)} 个镜头衔接清楚，可进入人工审核",
            issues=[],
            affected_shot_ids=[],
        )
```
