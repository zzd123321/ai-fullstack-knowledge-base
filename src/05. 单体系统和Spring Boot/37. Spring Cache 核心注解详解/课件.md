## 查看 Spring Cache 缓存

在介绍 Spring Cache 的三大核心注解之前，我们先来看一下如何查看位于 Spring Cache 中的缓存数据。

### 引入CacheManager

`CacheManager` 是 **Spring Cache 抽象层的核心接口**，它的职责非常单一且清晰：**管理项目中所有 `Cache`（缓存实例）的生命周期**，根据缓存名称提供对应的 `Cache` 对象。

```java
public interface CacheManager {    
    // 获取当前管理器下所有已注册的缓存名称集合
    Collection<String> getCacheNames();  
  
    // 根据缓存名称获取对应的 Cache 对象（如果不存在，具体行为由实现类决定）
    Cache getCache(String name);
}
```

Spring Boot 根据你引入的依赖和配置，会自动装配不同的 `CacheManager` 实现：

| 实现类                    | 对应技术                    | 特点                                                         |
| ------------------------- | --------------------------- | ------------------------------------------------------------ |
| ConcurrentMapCacheManager | `ConcurrentHashMap`（内存） | **默认兜底**。无需任何依赖，数据存在 JVM 内存中，重启即失。  |
| CaffeineCacheManager      | Caffeine（高性能本地缓存）  | 生产常用。比 `ConcurrentHashMap` 性能更高，支持过期、淘汰策略和统计。 |
| RedisCacheManager         | Redis（分布式缓存）         | 微服务常用。数据存于 Redis 服务器，支持多服务实例共享缓存。  |
| EhCacheCacheManager       | EhCache（老牌本地缓存）     | 需要引入 EhCache 依赖和配置文件。                            |
| JCacheCacheManager        | JSR-107 标准实现            | 适配任何支持 JCache 规范的缓存库（如 Ehcache 3.x）。         |

### 访问CacheManager

实现CacheManager访问工具类：基于ConcurrentHashMap

```java
@Service
public class CacheInspectorService {

    @Autowired
    private CacheManager cacheManager;

    /**
     * 查看所有缓存名称列表
     */
    public Map<String, Long> getAllCacheNamesAndSizes() {
        Map<String, Long> stats = new HashMap<>();
        for (String name : cacheManager.getCacheNames()) {
            Cache cache = cacheManager.getCache(name);
            if (cache != null && cache.getNativeCache() instanceof ConcurrentMap) {
                ConcurrentMap<?, ?> map = (ConcurrentMap<?, ?>) cache.getNativeCache();
                stats.put(name, (long) map.size());
            }
        }
        return stats;
    }  
  
    /**
     * 查看指定缓存名称下的所有键值对
     * @param cacheName 缓存名称（即 @Cacheable 中的 value）
     * @return 所有缓存条目
     */
    public Map<Object, Object> inspectCache(String cacheName) {
        Map<Object, Object> result = new HashMap<>();
        
        // 1. 获取 Cache 对象
        Cache cache = cacheManager.getCache(cacheName);
        if (cache == null) {
            throw new IllegalArgumentException("缓存 " + cacheName + " 不存在");
        }

        // 2. 获取原生缓存（此处一定是 ConcurrentHashMap）
        Object nativeCacheObj = cache.getNativeCache();
        if (!(nativeCacheObj instanceof ConcurrentMap)) {
            throw new IllegalStateException("底层缓存不是 ConcurrentHashMap，实际类型：" + nativeCacheObj.getClass());
        }

        // 3. 强转并遍历（注意这里不能直接返回原生 Map，防止外部修改）
        ConcurrentMap<Object, Object> nativeMap = (ConcurrentMap<Object, Object>) nativeCacheObj;
        result.putAll(nativeMap);
        
        return result;
    }
}
```

编写 REST 接口暴露查询功能（方便调试）：

```java
@RestController
@RequestMapping("/api/cache")
public class CacheController {

    @Autowired
    private CacheInspectorService cacheInspectorService;

    // 查询所有缓存名称及大小
    @GetMapping("/names")
    public Map<String, Long> getCacheNames() {
        return cacheInspectorService.getAllCacheNamesAndSizes();
    }

    // 查询特定缓存的具体内容
    @GetMapping("/{cacheName}")
    public Map<Object, Object> inspectCache(@PathVariable String cacheName) {
        return cacheInspectorService.inspectCache(cacheName);
    }
}
```



## @Cacheable 详解

### 基本回顾

`@Cacheable` 标记在方法上，表示该方法的返回值可以被缓存。当方法被调用时，先检查缓存中是否存在对应的键值，如果存在则直接返回缓存值，不执行方法体；否则执行方法体，并将返回值存入缓存。

```java
@Cacheable(value = "books", key = "#id")
public Book getBookById(Long id) {
    // 方法体仅在缓存未命中时执行
}
```

### 核心属性

| 属性                   | 类型            | 说明                           |
| ---------------------- | --------------- | ------------------------------ |
| `value` / `cacheNames` | `String[]`      | 缓存名称（必填），用于逻辑分区 |
| `key`                  | `String` (SpEL) | 缓存键，默认使用所有参数组合   |
| `condition`            | `String` (SpEL) | 条件缓存，满足条件时才缓存     |
| `unless`               | `String` (SpEL) | 排除缓存，满足条件时不缓存     |
| `sync`                 | `boolean`       | 是否同步（防止缓存击穿）       |
| `keyGenerator`         | `String`        | 自定义 KeyGenerator Bean 名称  |

> [!NOTE]
>
> 关于`condition`、`unless`和`sync`的使用方法后续会有专题进行详细介绍。

### 缓存名称（value / cacheNames）

- 可以指定一个或多个缓存名称
- 缓存名称用于逻辑分组，不同的缓存管理器可能对应不同的存储区域

```java
// 单个缓存名称
@Cacheable(value = "books")

// 多个缓存名称（会同时存入多个缓存）
@Cacheable(value = {"books", "popular-books"})

// 使用 cacheNames 属性（与 value 等价）
@Cacheable(cacheNames = "books")
```

> [!NOTE]
> 指定多个缓存名称时，方法执行后会同时将结果存入每个缓存中。查询时，只要任意一个缓存命中即可返回。

### 缓存键（key）

- 默认使用所有方法参数组合作为缓存键（相当于 `key = "#root.args"`）
- 可以通过 SpEL 表达式自定义键

#### 常用 SpEL 表达式

| 表达式             | 说明                                              |
| ------------------ | ------------------------------------------------- |
| `#id`              | 参数 `id` 的值                                    |
| `#book.id`         | 参数 `book` 的 `id` 属性                          |
| `#root.args[0]`    | 第一个参数（下标从 0 开始）                       |
| `#root.target`     | 当前目标对象                                      |
| `#root.methodName` | 当前方法名                                        |
| `'constant'`       | 固定字符串常量                                    |
| `#result`          | 方法返回值（仅在 `unless` 或 `@CachePut` 中可用） |

#### 示例

```java
// 使用参数 id 作为键
@Cacheable(value = "books", key = "#id")

// 使用参数 book 的 id 属性作为键
@Cacheable(value = "books", key = "#book.id")

// 组合多个参数作为键
@Cacheable(value = "books", key = "#author + '_' + #category")
@Cacheable(value = "books", key = "#author + '-' + #category")

// 使用固定字符串作为键（注意单引号）
@Cacheable(value = "books", key = "'all'")

// 使用参数下标
@Cacheable(value = "books", key = "#root.args[0]")
```

> [!CAUTION]
> 缓存键必须唯一。如果多个方法使用相同的缓存名称和键，它们会共享缓存数据，可能导致类型不匹配或数据混乱。



## @CachePut 详解

### 作用

`@CachePut` 总是执行方法体，并将方法返回值存入缓存。它通常用于数据更新操作，保证缓存与数据库同步。

```java
@CachePut(value = "books", key = "#book.id")
public Book updateBook(Book book) {
    // 更新数据库...
    return book;
}
```

### 与 @Cacheable 的对比

| 对比               | @Cacheable       | @CachePut      |
| ------------------ | ---------------- | -------------- |
| **是否执行方法体** | 缓存命中时不执行 | 总是执行       |
| **是否查询缓存**   | 是               | 否（直接执行） |
| **是否更新缓存**   | 缓存未命中时更新 | 总是更新       |
| **适用场景**       | 查询方法         | 更新/新增方法  |

### 核心属性

`@CachePut` 支持与 `@Cacheable` 相同的属性：`value`、`key`、`condition`、`unless`。

```java
// 只更新缓存，不更新缓存的情况（condition 控制）
@CachePut(value = "books", key = "#book.id", condition = "#book.price > 0")

// 不缓存空结果
@CachePut(value = "books", key = "#book.id", unless = "#result == null")
```

### 典型用法

```java
@Service
public class BookService {
    // 新增图书——将新增的图书放入缓存
    @CachePut(value = "books", key = "#book.id")
    public Book createBook(Book book) {
        // 保存到数据库...
        bookMapper.insert(book);
        return book;
    }

    // 更新图书——更新缓存
    @CachePut(value = "books", key = "#book.id")
    public Book updateBook(Book book) {
        // 更新数据库...
        bookMapper.updateById(book);
        return book;
    }
}
```

> [!NOTE]
> 使用 `@CachePut` 时，必须确保方法返回的对象包含完整的最新数据，因为缓存的是方法的返回值。



## @CacheEvict 详解

### 作用

`@CacheEvict` 用于清除缓存，通常在删除数据或批量更新时使用。

```java
@CacheEvict(value = "books", key = "#id")
public void deleteBook(Long id) {
    // 删除数据库记录...
}
```

### 核心属性

| 属性                   | 说明                                                   |
| ---------------------- | ------------------------------------------------------ |
| `value` / `cacheNames` | 缓存名称（必填）                                       |
| `key`                  | 缓存键（默认使用所有参数组合）                         |
| `allEntries`           | 是否清空整个缓存（默认为 `false`）                     |
| `beforeInvocation`     | 是否在方法执行前清除缓存（默认为 `false`，执行后清除） |

### 按 key 清除 vs 清空全部

```java
// 按 key 清除（只清除指定的缓存条目）
@CacheEvict(value = "books", key = "#id")
public void deleteBook(Long id) { ... }

// 清空整个缓存（清除所有 books 缓存条目）
@CacheEvict(value = "books", allEntries = true)
public void clearAllCache() { ... }
```

> [!NOTE]
> `allEntries = true` 时，`key` 属性将被忽略。

### beforeInvocation 属性

- `beforeInvocation = false`（默认）：方法执行成功后才清除缓存，如果方法抛出异常，缓存不会被清除。
- `beforeInvocation = true`：在执行方法之前清除缓存，无论方法是否执行成功。

```java
// 默认：方法执行成功后才清除缓存
@CacheEvict(value = "books", key = "#id")
public void deleteBook(Long id) { ... }

// 方法执行前清除缓存
@CacheEvict(value = "books", key = "#id", beforeInvocation = true)
public void deleteBook(Long id) { ... }
```

> [!NOTE]
> `beforeInvocation = true` 通常用于避免方法失败后缓存未清除。

### 典型用法

```java
@Service
public class BookService {
    // 删除图书——清除单条缓存
    @CacheEvict(value = "books", key = "#id")
    public void deleteBook(Long id) {
        bookMapper.deleteById(id);
    }

    // 批量删除——清空整个缓存
    @CacheEvict(value = "books", allEntries = true)
    public void deleteAllBooks() {
        // MyBatis-Plus 删除所有记录，wrapper 传 null 即可
        bookMapper.delete(null);
    }

    // 清除所有相关的缓存（包括列表缓存）
    @Caching(evict = {
        @CacheEvict(value = "books", key = "#id"),
        @CacheEvict(value = "books", key = "'all'")
    })
    public void deleteBookWithRelatedCache(Long id) {
        bookMapper.deleteById(id);
    }
}
```



## @Caching 详解

### 作用

`@Caching` 用于在一个方法上组合多个缓存操作（同时使用 `@Cacheable`、`@CachePut`、`@CacheEvict`）。

### 属性

| 属性        | 类型            | 说明               |
| ----------- | --------------- | ------------------ |
| `cacheable` | `@Cacheable[]`  | 多个 `@Cacheable`  |
| `put`       | `@CachePut[]`   | 多个 `@CachePut`   |
| `evict`     | `@CacheEvict[]` | 多个 `@CacheEvict` |

### 使用示例

```java
@Service
public class BookService {
    // 新增图书：清除 "all" 缓存，同时将新书加入缓存
    @Caching(
        put = @CachePut(value = "books", key = "#book.id"),
        evict = @CacheEvict(value = "books", key = "'all'")
    )
    public Book createBook(Book book) {
        bookMapper.insert(book);
        return book;
    }

    // 更新图书：更新单条缓存，清除 "all" 缓存
    @Caching(
        put = @CachePut(value = "books", key = "#book.id"),
        evict = @CacheEvict(value = "books", key = "'all'")
    )
    public Book updateBook(Book book) {
        bookMapper.updateById(book);
        return book;
    }

    // 删除图书：清除单条缓存和 "all" 缓存
    @Caching(
        evict = {
            @CacheEvict(value = "books", key = "#id"),
            @CacheEvict(value = "books", key = "'all'")
        }
    )
    public void deleteBook(Long id) {
        bookMapper.deleteById(id);
    }

    // 复杂场景：更新缓存同时查询缓存
    @Caching(
        cacheable = @Cacheable(value = "books", key = "#id"),
        put = @CachePut(value = "books", key = "#id")
    )
    public Book upsertBook(Long id, Book book) {
        // 存在则更新，不存在则新增（示意，实际需根据业务判断）
        bookMapper.insert(book);
        return book;
    }
}
```

> [!NOTE]
> `@Caching` 中 `cacheable` 和 `put` 的区别：`@Cacheable` 在缓存命中时不执行方法体，`@CachePut` 始终执行方法体并更新缓存。两者组合时需要谨慎，避免逻辑冲突。



## 实战：图书管理系统完整缓存策略

### 缓存策略设计

| 操作         | 缓存策略                                      |
| ------------ | --------------------------------------------- |
| 查询单本图书 | `@Cacheable` 缓存，按 ID 为键                 |
| 查询所有图书 | `@Cacheable` 缓存，使用固定键 `'all'`         |
| 新增图书     | `@CachePut` 缓存新书，清除 `'all'` 缓存       |
| 更新图书     | `@CachePut` 更新单条缓存，清除 `'all'` 缓存   |
| 删除图书     | `@CacheEvict` 清除单条缓存，清除 `'all'` 缓存 |

### 完整 Service 实现

```java
@Service
public class BookService {
    @Autowired
    private BookMapper bookMapper;

    // ========== 查询（@Cacheable） ==========

    @Cacheable(value = "books", key = "#id")
    public Book getBookById(Long id) {
        System.out.println("从数据库查询图书: " + id);
        return bookMapper.selectById(id);
    }

    @Cacheable(value = "books", key = "'all'")
    public List<Book> getAllBooks() {
        System.out.println("从数据库查询所有图书");
        return bookMapper.selectList(null);
    }

    // ========== 新增（@CachePut + 清除 all 缓存） ==========

    @Caching(
        put = @CachePut(value = "books", key = "#result.id"),
        evict = @CacheEvict(value = "books", key = "'all'")
    )
    public Book createBook(Book book) {
        System.out.println("新增图书: " + book.getTitle());
        bookMapper.insert(book);
        return book;
    }

    // ========== 更新（@CachePut + 清除 all 缓存） ==========

    @Caching(
        put = @CachePut(value = "books", key = "#book.id"),
        evict = @CacheEvict(value = "books", key = "'all'")
    )
    public Book updateBook(Book book) {
        System.out.println("更新图书: " + book.getId());
        bookMapper.updateById(book);
        return book;
    }

    // ========== 删除（清除单条 + 清除 all 缓存） ==========

    @Caching(
        evict = {
            @CacheEvict(value = "books", key = "#id"),
            @CacheEvict(value = "books", key = "'all'")
        }
    )
    public void deleteBook(Long id) {
        System.out.println("删除图书: " + id);
        bookMapper.deleteById(id);
    }
}
```

### 测试验证

**场景：新增图书后缓存更新**

1. 调用 `GET /api/books`（首次查询，缓存 `'all'`）
2. 调用 `POST /api/books` 新增一本图书（执行 `createBook`：新增单条缓存，清除 `'all'` 缓存）
3. 再次调用 `GET /api/books`（缓存被清除，重新查询数据库，重新缓存 `'all'`）

**预期结果：** 新增图书后，`'all'` 缓存被清除，保证下次查询获取最新数据。



## 注意事项

### 1. @Cacheable 与 @CachePut 的兼容性

- 同一个方法上不能同时使用 `@Cacheable` 和 `@CachePut`（两者语义冲突）。如需组合，使用 `@Caching`。

### 2. 缓存更新时机

- `@CachePut` 总是在方法执行后更新缓存，无论方法是否抛出异常（除非 `unless` 条件阻止）。
- `@CacheEvict` 默认在方法执行后清除缓存，若方法抛异常，缓存不会被清除。

### 3. 缓存键的冲突

- 确保不同的方法（尤其使用相同缓存名称时）使用不同的键，避免数据覆盖。
- 例如：`getBookById` 使用 `key="#id"`，`getAllBooks` 使用 `key="'all'"`，两者不会冲突。

### 4. 方法返回值类型

- 缓存存储的是方法的返回值，因此方法返回类型必须与缓存值类型一致。
- 使用 `@CachePut` 时，返回的对象必须是完整的，否则缓存中存储的是不完整数据。



## 小结

本节课我们学习了：

1.  **CacheManager的使用方式**
2. **@Cacheable 详细用法**：
   - `value`：缓存名称
   - `key`：自定义缓存键（SpEL）
3. **@CachePut**：总是执行方法体，更新缓存，适用于数据更新/新增操作。
4. **@CacheEvict**：
   - `key`：按指定键清除缓存
   - `allEntries`：清空整个缓存
   - `beforeInvocation`：控制清除时机
5. **@Caching**：组合多个缓存操作，适用于复杂场景。
6. **实战应用**：为图书管理系统设计了完整的缓存策略。
