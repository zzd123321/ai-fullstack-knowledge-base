# 数据层测试：@MybatisPlusTest

## 课程目标

- 理解 MyBatis-Plus 数据层测试的定位和加载范围
- 掌握 @MybatisPlusTest 的使用方法
- 掌握 Mapper 派生查询、条件构造器、自定义 SQL 的测试
- 掌握分页和排序查询的测试
- 掌握使用 @Sql 加载测试数据
- 能够为 BookMapper 的所有方法编写数据层测试



## 回顾与导入

在上一讲中，我们使用 `@WebMvcTest` 测试了 Controller 层。Controller 依赖的 Service 使用 `@MockBean` 模拟，**没有真正访问数据库**：

```java
@WebMvcTest(BookController.class)
class BookControllerTest {
    @MockBean
    private BookService bookService;   // Mock，不访问数据库

    @Test
    void testGetBook() throws Exception {
        when(bookService.getBookById(1L)).thenReturn(book);  // 直接返回 Mock 数据
        // ...
    }
}
```

但以下问题无法通过 Web 层测试验证：

| 待验证项                | 说明                                     |
| ----------------------- | ---------------------------------------- |
| **Mapper 方法是否正确** | `selectByAuthor` 是否真正按作者查询      |
| **SQL 语法是否正确**    | 注解或 XML 中的 SQL 是否有语法错误       |
| **条件构造器**          | LambdaQueryWrapper 的条件是否正确        |
| **分页插件**            | Page 对象是否正确分页                    |
| **字段映射**            | 数据库列名与 Java 属性是否正确映射       |
| **自定义 SQL**          | @Select 和 XML 中的 SQL 是否返回预期结果 |

这些都需要针对**数据访问层**编写测试。

```mermaid
flowchart LR
    A[Web 层测试<br/>@WebMvcTest] --> B[Mock Service]
    C[Service 单元测试<br/>Mockito] --> D[Mock Mapper]
    E[数据层测试<br/>@MybatisPlusTest] --> F[真实数据库<br/>内嵌 H2]

    style E fill:#e8f5e9
    style F fill:#e8f5e9
```

本节课将使用 `@MybatisPlusTest` 为 `BookMapper` 编写完整的数据层测试。



## @MybatisPlusTest 概述

### 什么是 @MybatisPlusTest

**@MybatisPlusTest** 是 MyBatis-Plus 官方提供的**测试切片注解**，它只加载 MyBatis-Plus 相关组件，不启动 Web 服务器、不加载 Service 和 Controller。

```mermaid
flowchart TB
    A[完整上下文<br/>@SpringBootTest] --> B[所有组件]
    C[数据层切片<br/>@MybatisPlusTest] --> D[DataSource]
    C --> E[SqlSessionFactory]
    C --> F[Mapper 接口]
    C --> G[事务管理]

    style C fill:#e8f5e9
```

### 加载的组件

| 组件                          | 是否加载     |
| ----------------------------- | ------------ |
| `DataSource`                  | ✅            |
| `SqlSessionFactory`           | ✅            |
| `Mapper` 接口                 | ✅            |
| `TransactionManager`          | ✅            |
| `@Service` / `@Component`     | ❌            |
| `@Controller`                 | ❌            |
| MyBatis-Plus 拦截器（分页等） | ⚠️ 需显式导入 |

### 核心特性

| 特性             | 说明                                     |
| ---------------- | ---------------------------------------- |
| **内嵌数据库**   | 默认使用 H2 内存数据库，无需外部依赖     |
| **自动事务回滚** | 每个测试方法在事务中执行，测试结束后回滚 |
| **测试数据隔离** | 每个测试方法的数据独立，互不影响         |
| **快速启动**     | 只加载 MyBatis-Plus 组件，启动速度快     |

> [!NOTE]
> `@MybatisPlusTest` 的测试方法默认使用 `@Transactional`，测试完成后自动回滚。这意味着测试中插入的数据不会持久化到数据库，每次测试都在干净的环境中执行。

### @MybatisPlusTest 与 @SpringBootTest 对比

| 对比         | @MybatisPlusTest         | @SpringBootTest  |
| ------------ | ------------------------ | ---------------- |
| **加载范围** | 只加载 MyBatis-Plus 组件 | 完整上下文       |
| **速度**     | 快                       | 慢               |
| **数据库**   | 内嵌 H2（默认）          | 项目配置的数据库 |
| **事务回滚** | 自动回滚                 | 默认不回滚       |
| **适用场景** | Mapper 测试              | 端到端集成测试   |

## 使用 @MybatisPlusTest

### 基本测试类结构

```java
@MybatisPlusTest
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
@DisplayName("BookMapper 数据层测试")
class BookMapperTest {

    @Autowired
    private BookMapper bookMapper;

    @Test
    @DisplayName("根据 ID 查询图书")
    void testSelectById() {
        // ...
    }
}
```

> [!NOTE]
> - `@MybatisPlusTest` 会加载 Mapper 和 SqlSessionFactory。
> - `@AutoConfigureTestDatabase(replace = Replace.NONE)` 表示使用配置的数据源（H2），而不是替换为其他内嵌数据库。

### 分页插件配置

如果 Mapper 中使用了分页插件（如 `selectPage`），需要在测试中显式导入 MyBatis-Plus 拦截器配置：

```java
@MybatisPlusTest
@Import(MybatisPlusConfig.class)   // 导入分页插件等配置
class BookMapperTest {
    // ...
}
```

**MybatisPlusConfig 配置：**

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.POSTGRE_SQL));
        return interceptor;
    }
}
```

> [!NOTE]
> 生产环境中 `DbType.POSTGRE_SQL`，测试环境中使用 H2 时，需注意分页方言的适配。可以通过 `@TestConfiguration` 定义测试专用的配置。

**测试专用配置（推荐）：**

```java
@TestConfiguration
public class TestMybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor testMybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // H2 方言
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.H2));
        return interceptor;
    }
}
```

```java
@MybatisPlusTest
@Import(TestMybatisPlusConfig.class)
class BookMapperTest {
    // ...
}
```


### 被测 Mapper

以图书管理系统的 `BookMapper` 为例：

```java
@Mapper
public interface BookMapper extends BaseMapper<Book> {

    /**
     * 根据作者查询
     */
    @Select("SELECT * FROM book WHERE author = #{author}")
    List<Book> selectByAuthor(@Param("author") String author);

    /**
     * 更新库存
     */
    @Update("UPDATE book SET stock = stock + #{delta} WHERE id = #{id}")
    int updateStock(@Param("id") Long id, @Param("delta") int delta);
}
```

## 使用 @Sql 加载测试数据

### 什么是 @Sql

`@Sql` 注解用于在测试方法执行前后执行 SQL 脚本，适合准备测试数据或清理数据。

### 方式一：内联 SQL 语句

```java
@Test
@Sql(statements = {
        "INSERT INTO book (title, author, price, stock, category) VALUES ('测试书', '作者', 50.0, 5, '测试')"
})
void testWithInlineSql() {
    // ...
}
```

### 方式二：加载 SQL 文件

**测试资源目录：** `src/test/resources/sql/book-test-data.sql`

```sql
-- book-test-data.sql
DELETE FROM book;

INSERT INTO book (title, author, price, stock, category) VALUES
('测试书1', '作者1', 10.0, 1, '测试'),
('测试书2', '作者2', 20.0, 2, '测试'),
('测试书3', '作者3', 30.0, 3, '测试');
```

**在测试中使用：**

```java
@Test
@Sql("/sql/book-test-data.sql")
void testWithSqlFile() {
    List<Book> books = bookMapper.selectByCategory("测试");
    assertThat(books).hasSize(3);
}
```

### @Sql 的执行时机

| 属性             | 说明                   | 默认值               |
| ---------------- | ---------------------- | -------------------- |
| `executionPhase` | 执行阶段               | `BEFORE_TEST_METHOD` |
| `config`         | 配置（如编码、分隔符） | 默认                 |

**在测试后执行清理 SQL：**

```java
@Test
@Sql(
    scripts = "/sql/book-test-data.sql",
    executionPhase = Sql.ExecutionPhase.BEFORE_TEST_METHOD
)
@Sql(
    scripts = "/sql/cleanup.sql",
    executionPhase = Sql.ExecutionPhase.AFTER_TEST_METHOD
)
void testWithBeforeAndAfterSql() {
    // ...
}
```

### 类级别使用 @Sql

```java
@MybatisPlusTest
@Sql("/sql/book-test-data.sql")   // 所有测试方法执行前都执行
class BookMapperTest {
    // ...
}
```

> [!NOTE]
> 使用 `@Sql` 时，脚本中的 `DELETE FROM book` 会清除 `@BeforeEach` 中插入的数据。注意执行顺序：`@BeforeEach` → `@Sql`（如果配置为 BEFORE）→ 测试方法。



## 测试断言最佳实践

### 使用 AssertJ 流式断言

`@MybatisPlusTest` 默认包含 AssertJ，推荐使用流式断言：

```java
// JUnit 断言
assertEquals(3, books.size());
assertEquals("Spring Boot 实战", books.get(0).getTitle());

// AssertJ 断言（推荐）
assertThat(books)
        .hasSize(3)
        .extracting(Book::getTitle)
        .containsExactlyInAnyOrder("Spring Boot 实战", "Java 核心技术", "百年孤独");
```

### 常用 AssertJ 断言

| 断言                                               | 说明             |
| -------------------------------------------------- | ---------------- |
| `assertThat(list).hasSize(n)`                      | 集合大小         |
| `assertThat(list).isEmpty()`                       | 集合为空         |
| `assertThat(list).isNotEmpty()`                    | 集合非空         |
| `assertThat(list).extracting(Function)`            | 提取字段         |
| `assertThat(list).containsExactly(a, b)`           | 精确包含（顺序） |
| `assertThat(list).containsExactlyInAnyOrder(a, b)` | 精确包含（无序） |
| `assertThat(list).contains(a)`                     | 包含某元素       |
| `assertThat(value).isEqualTo(expected)`            | 相等             |
| `assertThat(value).isCloseTo(expected, offset)`    | 浮点数近似相等   |
| `assertThat(value).isNotNull()`                    | 非空             |
| `assertThat(value).isNull()`                       | 为 null          |
| `assertThat(value).isPositive()`                   | 正数             |
| `assertThat(value).isGreaterThan(n)`               | 大于             |

### 对于单条记录的断言

```java
// 方式一：判空后断言字段
Book result = bookMapper.selectById(1L);
assertThat(result).isNotNull();
assertThat(result.getTitle()).isEqualTo("Spring Boot 实战");

// 方式二：使用 extracting 链式断言
assertThat(result)
        .extracting(Book::getTitle, Book::getAuthor)
        .containsExactly("Spring Boot 实战", "Craig Walls");
```



## 注意事项

### 1. 测试方法默认回滚

`@MybatisPlusTest` 的测试方法默认在事务中执行，测试结束后回滚。这意味着：

```java
@Test
void test1() {
    bookMapper.insert(new Book(...));
    assertThat(bookMapper.selectCount(null)).isEqualTo(4);
}

@Test
void test2() {
    // 不会看到 test1 中的数据
    assertThat(bookMapper.selectCount(null)).isEqualTo(3);
}
```

**如果需要不回滚：**

```java
@Test
@Rollback(false)   // 提交事务，数据保留
void testNoRollback() { ... }

@Test
@Commit            // 相当于 @Rollback(false)
void testCommit() { ... }
```

### 2. 内嵌数据库 H2

`@MybatisPlusTest` 默认使用内嵌 H2 数据库。H2 的 SQL 语法可能与 PostgreSQL 有差异，尤其是：

- 序列生成方式
- 函数名称（如 `ILIKE`、`DATE_TRUNC`）
- 数据类型
- `LIMIT` / `OFFSET` 语法

**生产环境使用 PostgreSQL 时，H2 测试可能通过但生产失败。**

**解决方案：**

- 使用 H2 的 PostgreSQL 兼容模式（`MODE=PostgreSQL`）

### 3. Mapper 需要手动清空表

与 JPA 的 `TestEntityManager` 不同，MyBatis-Plus 没有自动清空表的机制。在 `@BeforeEach` 中需要手动清空：

```java
@BeforeEach
void setUp() {
    bookMapper.delete(null);   // 清空表
    // 插入测试数据
}
```

### 4. 分页插件需要显式导入

`@MybatisPlusTest` **不会自动加载** `MybatisPlusInterceptor`（分页插件）。如果 Mapper 中使用 `selectPage`，需要在测试中显式导入配置：

```java
@MybatisPlusTest
@Import(TestMybatisPlusConfig.class)
class BookMapperTest {
    // ...
}
```

### 5. 避免在测试中依赖自增 ID 的具体值

```java
// ❌ 错误：假设 ID 从 1 开始
Book saved = bookMapper.insert(book);
assertThat(book.getId()).isEqualTo(1L);

// ✅ 正确：只断言 ID 存在
assertThat(book.getId()).isNotNull();
```

### 6. 测试类之间共享状态

由于每个测试方法回滚，测试类之间是隔离的。但 `@BeforeEach` 中插入的数据会在每个测试方法执行前重新创建，避免数据冲突。




## 小结

本节课我们学习了：

1. **@MybatisPlusTest 概述**：
   - 只加载 MyBatis-Plus 相关组件（DataSource、SqlSessionFactory、Mapper）
   - 默认使用 H2 内嵌数据库
   - 测试方法默认回滚
2. **Mapper 测试**：
   - 基础 CRUD（insert、selectById、updateById、deleteById）
   - 条件构造器（LambdaQueryWrapper、LambdaUpdateWrapper）
   - @Select 注解方法
   - 分页与排序（Page + PaginationInnerInterceptor）
3. **使用 @Sql 加载测试数据**：内联 SQL 和 SQL 文件
4. **实战应用**：为 `BookMapper` 编写完整的数据层测试
