# Wiki 维护规则

## 目标、方案与实现状态

- 目标：将企业资料整合成可浏览、可追溯、能继续维护的知识页，保留时间、版本和证据边界。
- 选定方案：原始资料副本＋Markdown 来源／实体／主题页面；标准相对 Markdown 链接；目录、来源清单和处理记录。
- 原因：本批 27 份来源规模较小，直接浏览和文件搜索足以检查证据，无需新增数据库或依赖。
- 实现状态：已完成 2026-11-04 的一次编排与校验；下述流程是后续维护契约，没有后台任务自动执行。

## 三层目录

1. `raw/`：来源完整副本，由资料维护者管理，Agent 不改写证据。保留原目录以维护原文到图片的相对链接。确需更新来源时，保留旧版本或先记录内容差异，不静默替换历史证据。
2. `wiki/`：可重建的衍生层。`sources` 一来源一页；`entities` 按客户、配置、软件等稳定身份整理；`concepts` 综合多个来源。`index.md` 为总导航。
3. 本文件：知识格式和摄入、查询、检查规则；`AGENTS.md` 为维护入口，`log.md` 记录操作，`manifest.json` 记录逐来源血缘与哈希。

## 页面格式与身份

来源页文件名使用文档／图片编号；实体、主题页使用明确中文标题。所有内容页带 YAML frontmatter：`id`、`title`、`type`、`compiled_at`、`knowledge_as_of`、`sources`；来源页另带 `raw_path` 和 `sha256`。来源 `sources` 含自身编号，表示对应原始证据；综合页列其实际使用的来源编号。

- 关键事实或表格紧邻来源链接；来源页提供原始文件入口。综合推断明确写出“综合判断”“推理”或计算依据。
- 文档元信息原样保留其日期、版本、状态与阅读范围，不把编排日期当成事实更新日期。
- 使用标准相对 Markdown 链接，保持文件可搬运；每个内容页链接回总索引，列出引用本页的其他内容页。
- 相同客户使用 C-HC／C-YL／C-HY，商机和部署 ID 单独保留；A200 系列与 CFG-A200-2／4 不混同；L23 与 S30 不合并；ISSUE-017 与 LAB-0816-017 不合并。
- 引用来源有“销售内部”等阅读范围。本目录为内部整合材料，范围标签不构成技术权限控制；对外共享前由资料维护者按原范围筛选。

## 摄入 Ingest

1. 先清点新增／变更／移除来源，读取全文和图片；不能只按标题生成摘要。图片提取标明方法与不可读部分，不臆造隐含参数。
2. 在保留证据的前提下添加原始文件并登记路径、字节数、SHA-256；已存在相同来源不得重复编页。
3. 建立或修订来源页，提取日期、状态、版本、数据条件、限制与关联编号。
4. 搜索索引及已有实体／主题页，整合新旧证据；同实体优先更新，不仅追加摘要。
5. 对比时间、适用版本、测量范围与状态。明确替代关系才能标为历史；无法解释的矛盾保留双方来源，登记待核对，不自行裁决。
6. 沿来源页的引用反查受影响知识页，来源删除或撤回时重新评估结论，不保留无支持的事实。
7. 更新索引、反向链接、清单和处理记录，完成本地检查。重要业务承诺仍需要正式证据，Agent 不能把自身摘要当作新的独立证明。

## 查询 Query

先从 `wiki/index.md` 定位主题／实体，再读取关联来源；问题涉及报价、精度、版本、计划或验收时回查原文。回答包含证据日期和适用条件；缺信息就列缺口。不把全部 Wiki 一次塞入上下文作为唯一方法。

用户要求保存分析时，可把带完整证据的分析写回主题页；它仍是衍生结论，不成为证明自身的来源。普通询问不自动授权写入。

## 检查 Lint

- 结构：每份原始文件有来源页及清单记录，哈希与副本一致；每个 Wiki 页面在索引中；链接和图片存在；无悬空来源编号与重复稳定 ID。
- 血缘：综合页实际引用来源与 `sources`、清单对应；反向链接可回到引用页；修改后同步更新。
- 语义：价格日期、审批状态、历史替代、测试条件、计划与完成、实验室与现场、Q4 与 FP16 不混同。
- 数值：重算金额和预算差，核对性能表与原文；不把吞吐合计换成个人速率或把 P95 改成全部请求保证。
- 图片：图表与正文交叉核对；草案地址保持待确认；照片不作为运行证明；聊天中提到但未提供的材料只列待办。
- 记录检查范围和未验证项。链接检查不能证明事实正确，静态文档编排不能证明生产服务已实现能力。
