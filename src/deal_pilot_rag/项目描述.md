# 项目

## 项目背景

### 公司背景-企业在做什么

澄算科技是一家提供训推一体机与私有化 AI 解决方案的科技公司，主要服务制造企业、客服服务商和工程设计公司，帮助客户在内部环境中部署大模型、接入业务系统，并完成应用落地与运维支持。

### 遇到的问题

这类业务的销售周期较长，需要销售、售前、技术和商务共同参与。从获得客户线索开始，团队要逐步明确需求、评估方案、组织测试、准备报价、处理客户异议，再推进签约与交付衔接。每个阶段都需要形成相应材料，并完成必要的内部审核。

随着商机数量增加，销售团队越来越依赖个人经验和人工协调推进工作：新人不知道下一步该问什么、准备什么，资深销售反复整理材料、协调资源，售前与商务需要多次确认需求和方案变化。客户信息、产品经验和审批进度分散在不同人员手中，容易出现跟进遗漏、重复沟通、材料口径不一致等问题，管理者也难以及时判断商机卡在哪里、需要谁来处理。

例如，一名新销售接到某大型制造集团的需求：“计划在总部和八家工厂部署训推一体机及配套应用，供两千名工程师查询工艺资料、分析生产问题，首期总预算一千五百万元，包含设备、软件、系统集成和实施服务，希望下周看到初步方案和报价。”销售只记下人数和总预算，就请售前推荐设备。售前介入后才发现，还没有确认各厂区的部署规模、高峰使用量、现有系统版本和验收要求，只能再次约客户补充沟通。客户随后提出各厂区必须保留原有业务系统，销售将要求记在聊天中，却没有同步给商务，导致报价漏掉了多套系统的适配和跨厂区实施费用。

等到补齐费用，总价又超出预算，需要申请折扣。销售以为售前会协调，售前以为商务已经提交，直到客户催问才发现审批尚未发起。最终，团队反复修改方案和报价，仍未按约定时间交出完整材料。问题贯穿了整笔商机：需求漏问、变更漏传、费用漏算、审批漏办，每个人都在忙，却没有人掌握完整的推进状态。

### 需要的产品

为此，澄算启动“商机智航”，计划向销售部门交付一套 AI 驱动的销售协作系统。系统以客户线索为起点，结合企业产品信息、历史经验和业务规则，协助制定跟进计划、推进阶段任务，逐步产出需求摘要、方案建议、测试计划、报价草稿和客户沟通材料；在技术评审、折扣审批和对外发送等关键节点交由相应人员确认，再依据反馈继续推进。项目将分阶段引入多 Agent 协作，让企业积累的信息与经验参与实际销售流程，减少重复劳动与协作遗漏，提高商机推进效率。

对于上面这笔商机，商机智航需要支持以下处理过程：

1. **接到线索，明确下一步。** 销售录入客户沟通记录后，系统整理需求摘要，按总部与各厂区列出部署规模、并发使用量、现有系统和验收标准等需要确认的问题，生成跟进任务，并记录负责人和客户要求的交付时间。
2. **需求变化，同步相关工作。** 客户确认各厂区保留原有系统后，系统更新需求记录，提示售前逐项评估适配方案，并将必要的软件、系统适配与跨厂区实施服务纳入报价准备清单。售前审核方案与验证计划，尚未验证的内容明确列为待办。
3. **报价超预算，进入审批。** 系统汇总设备、软件和服务费用，发现超出预算后，辅助形成折扣申请，交销售确认并提交相应负责人审批。审批状态与待处理人持续可见，未获批准的金额保留为内部草稿。
4. **材料齐备，再对外交付。** 技术评审和商务审批完成后，系统按确认结果整理方案、正式报价及待客户确认事项，由销售审核后发送；随后根据客户反馈生成下一轮跟进任务。若验证或审批未完成，则提醒责任人，并提示销售及时与客户调整交付安排。

这样，原先依赖个人记忆和群聊传递的工作，就有了明确的任务、产出、负责人和推进条件。销售知道下一步做什么，售前和商务依据同一份需求协作，管理者能看到具体阻塞点，客户也能获得口径一致、经过审核的材料。

## 项目名称

商机智航——企业数字资产价值重塑

## 项目描述

面向训推一体机企业销售部门的 AI 销售协作系统，采用 FDE 交付模式，围绕线索跟进、需求分析、方案准备、报价审批与交付衔接，分阶段建设知识检索、多 Agent 协作和流程推进能力。结合企业产品信息与业务规则，辅助生成阶段材料、跟踪待办，并在关键节点引入人工审核，推动企业数字资产融入销售工作，提升商机推进效率与跨部门协作质量。

## 经验/方案

- 建立 **Agent Benchmark 回归基线**，持续纳入真实场景评估数据集，为每轮迭代提供可对照的效果评估与回归依据。
- 构建覆盖**成本、线上评估和异常错误**的告警流水线，接入企业 **SMS** 系统实现多渠道通知，提升关键问题的发现与响应效率。
- 通过**会话粘性路由**保持同一会话的模型路由一致性，避免跨模型切换造成 **KV Cache** 失效，提升会话请求的推理效率。
- 基于 **LiteLLM** 实施模型与网关双层并发控制：模型侧采用**熔断与回退**机制保障调用连续性，网关侧通过**请求排队与等待**缓解瞬时流量压力，提升服务可用性。
- 引入 **Nacos AI Registry** 统一治理 **Prompt、Skill、MCP 与 AgentSpec**，打通 AI 能力的注册发现与动态配置，降低资源分散和版本割裂带来的治理成本。
- 基于 **OpenSandbox** 构建用户级隔离执行环境，通过**私有卷持久化与共享卷只读复用**，兼顾 Agent 执行隔离、工作数据延续与公共能力复用。
- 通过 **BlockNode Tree** 实现精细结构化的切片索引，确保每个切片**语义完整**、**来源可溯**、**版本可控**，并可通过切片间的**父子引用**还原上下文。
- 构建完善的**多模态RAG**索引流水线，结合版本对比实现**实时增量索引**与旧版本清理。
- 基于 HNSW 建立 **Milvus** 的 ANN 索引，实现 **稠密 + BM25稀疏** 的多路召回，然后基于 RRF / Weighted / Model 多策略 Rerank
- 实现 **Agentic RAG** 检索，构建“首轮材料注入＋自主检索＋结构补查”的多跳推理机制，支持 Agent 根据已有证据改写查询、限定来源，并沿父块与引用块补充上下文。
- 实现 **Milvus Schema 兼容性预检与原地同步**，支持字段新增、字符串扩容及历史元数据局部回填。
- Milvus Entity 附带 **Role Metadata**，检索时强制新增角色筛选条件，实现严格带权限的数据检索。
- 实现多数据源归一化策略，将不同来源（飞书文档、本地文件、对象存储等）、不同格式（pdf、图片、markdown、word、ppt等）的数据，通过不同策略（**MinerU**、**PaddleOCR**、**Unstructrued**）归一化为标准格式。
- 针对全量知识图谱抽取成本高、维护投入大的问题，设计 **全量文档索引＋精选知识图谱** 的双路索引方案：全量文档进入 **Milvus**，围绕高价值业务数据抽取实体与关系并存入 **Neo4j**，按需构建社区，同时支持管理后台人工录入实体关系，兼顾知识覆盖、关系表达与建设成本。
- [可选]针对客户、产品、项目等关联信息分散、单次文档检索难以获取完整证据的问题，设计 **文档检索＋图谱检索** 的双路召回方案：用户问题并行检索 Milvus 文档片段与 Neo4j 图谱知识，通过向量匹配定位相关实体及可选社区信息，汇总两路结果，并通过系统提示词明确不同材料的含义，为回答提供文本与关系两类依据。
- [可选]设计 **Graph RAG 与 Agentic RAG 协同**的多跳检索方案，在现有文档搜索、切片补查工具之外增加图谱查询工具，由 Agent 根据首轮结果和证据缺口自主选择检索路径，交替补充文档细节与实体关系，形成“首轮双路召回—按需多轮补查—综合证据回答”的检索闭环。
